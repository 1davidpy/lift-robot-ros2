# 配置2与七舵机遥控

配置源：config/config2.json。CMake直接读取这个独立文件，生成常量并编译到芯片Flash；
不依赖Qt运行时RAM限位。重启自动加载四轴限位，加载限位不产生移动。
config/machines.json保留历史配置，本版本不从该文件编译。

BL/BR单按控制俯仰，同时按两键后退且俯仰停止；后退组合优先于L1/R1。
BR不再调速。底盘固定回转1000、履带3000；大臂250、小臂500、俯仰和夹爪200。
保持原摇杆的方向及每个摇杆较大位移轴优先规则，RX独立发送8号通道。

旧v1包被拒绝，必须配套更新两端。

## 坐标与编码器偏移

截图限位记录时，1/2/3号是模式1，8号是模式0；本次读回各轴偏移寄存器为85。
配置保存reference_mode及encoder_offset，限位数字保持截图原值。
控制需要位置模式0，1/2/3号该模式的原始反馈加85，换算到原标定参考坐标；
对应目标减85后下发。8号参考模式本来就是0，不做这个加减。
STATUS2/READINGS及Qt显示参考坐标；POSITION_DIAG显示舵机原始坐标和偏移。
仅在偏移与配置一致、值不跨0..4095时允许使用；不写偏移寄存器或重设中心。

模式准备在卸力下等待至少100ms，再要求三次反馈稳定，并检查模式切换前后
换算后的参考位置差不超过2。若不一致，准备失败且保持暂停，不追旧目标。
此检查用于防止已观察到的模式切换后反馈更新晚于应答，及未知姿态/坐标变化。
更换舵机、重新校中或修改偏移后须重新核对该元数据和机械端点。

## 准备及控制

2026-10-21起，上电先只读发现舵机。全部在线、输入中立且四位置轴反馈稳定约1秒后，
单片机自动将未带力矩的舵机准备为正确模式：底盘零速度、位置轴实时位置保持，不回中。
已有正确模式/力矩/近距离保持目标时直接采用，不重复卸力。错误模式下仍带力矩的轴不自动卸力，
坐标/偏移异常或准备失败仍停止，不能绕过。准备后重新要求中立约1秒才允许运动。
此流程不依赖Linux、Qt或串口命令；舵机晚于主控供电也能在发现后准备。
需要重新准备时，先支撑大小臂与夹爪、履带架空、回转及线缆安全、遥控中立，
在Qt点击“准备遥控”（PREPARE_REMOTE）：

1. 暂停遥控并停止底盘。
2. 4/5/6卸力、轮式模式1、验证零目标速度，等待模式稳定后恢复力矩。
3. 1/2/3/8分别卸力、位置模式0、等待稳定并校验参考坐标不变，
   写入实时当前位置目标并读回确认，然后恢复力矩。
4. 全部位置轴准备成功后等待中立1秒。失败不自动重试。

遥控按每20ms的配置速度推进，四轴步长分别5/10/4/4，单次最多10。
前一目标差值须不超过96减步长减4；规划领先最多92，预留4计数重新采样裕量。
独立遥控驱动接口验证新读数、位置模式及力矩，每次差值不超过96、速度不超过500；
手动标定仍使用独立步长10、速度100的约束。带载保持读数与目标可能相差约11，
启动接管容差为16，配合模式、偏移和限位检查，仍拒绝相差85的旧中心。
目标不随持续输入无限累积，兼顾舵机死区与小步控制。
不直接发送整段行程终点。释放或反向先保持新读数；约200ms无线超时停止并解除允许，
重新连接仍需中立1秒。越界轴只能向范围内缓慢回退，绝不跳到下限/上限。
小步回退允许穿过最近边界进入范围内，避免死区使轴停在边界外。
截图2号2143低于下限2223，因此外向动作被拒绝、内向动作允许。

## Qt与保存

双击Projects/Qt_centers/QtCenters.exe，115200 8N1连接COM6。
默认加载同一config2.json，保存保留参考模式/偏移。保存文件不会自动下发或更新已烧录Flash；
修改永久配置后仍须重编译和烧录。运行时LIMIT只能缩小Flash安全范围，CLEAR恢复Flash值。
“准备标定”暂停整个遥控，手动速度1..100、每次最多10，越界同样只允许向内。
标定完成后用“恢复遥控”（RESUME_REMOTE），无需重复卸力；模式不正确则先准备。
“暂停遥控”或“全部停止”保持已运动位置轴的新读数，并将底盘速度置零。
软件停止不能代替动力断电，卸力时务必支撑机构。

## 只读诊断

```text
FLASH_LIMITS
STATUS
READINGS
MODES
POSITION_DIAG <axis:0|1|2|3|4>
POSITION_DEADBAND <axis:0|1|2|3|4>
SERVO_REG <axis:0|1|2|3|4> <address:0..254>
REMOTE_INPUT
BUS_DIAG
```

FLASH_LIMITS返回Flash配置名称和八个限位数字，不返回临时RAM覆盖值。
REMOTE_STATE返回enabled、armed、ready_mask、recovery_mask，位按轴0/1/2/4，全准备为23。
POSITION_DIAG返回ID、模式、力矩、原始当前位置、原始目标位置、目标速度、偏移原始字。
POSITION_DEADBAND只读返回ID及26/27号死区寄存器，不改参数。
SERVO_REG只读返回ID、起始地址和两个相邻字节的小端原始值，供PID/负载/电源排查。
REMOTE_INPUT返回最后接收的left/right/swing/boom/arm/pitch/gripper七通道、距接收的tick数
及接收计数（tick为1ms）。暂停遥控时仍可观察输入，且不会驱动电机。
同日后续离线修复与次日烧录流程见remote_fix_2026-10-14.md。
最新烧录和大臂抬升复测见hardware_test_2026-10-15.md。模拟测试不能替代实际端点、方向和载荷确认。

## Linux / Agent 串口控制扩展（2026-10-16）

Linux 上位机位于仓库 `project/ctrl`，Qt 总览页提供七通道本体控制。
新版增加 `CAPS` → `CAPS HOST_CONTROL_V2`、`HOST_BEGIN`、
`HOST_CONTROL left right swing boom arm pitch gripper`、`HOST_END`。
履带通道为-6..6，其余-10..10，速度及位置安全约束沿用本页Config2值。
旧版无此能力，不可用原WHEEL/JOG命令绕过限制。

HOST_BEGIN开启本体会话，不准备舵机或切换模式，正确模式/力矩/保持目标及中立1秒仍是前提。
无线一直接收：无线中立帧不覆盖本体动作；任一无线通道非零即取消本体整条动作，
发送HOST_PREEMPTED，遥控优先控制。遥控自身也需连续回中约1秒，未允许的偏置输入只取消本体、不运动。
遥控回中后旧本体动作不重放。HOST_BEGIN遇到非零无线输入返回ERR RADIO_ACTIVE，不停止遥控。
HOST_END只结束本体，迟到帧和结束命令不会覆盖已经优先的遥控器。
主机50ms续帧，约200ms失联停止主机并结束会话，无线仍开放；无线失联不停止有效主机会话。
STOP_CONTROL停止双方并要求遥控回中约1秒自动恢复，不永久暂停无线。
PAUSE_REMOTE、标定准备和硬件故障仍可显式暂停；RESUME_REMOTE用于维护暂停后的恢复。
STATUS增加CONTROL_STATE host_session host_streaming radio_armed radio_active；REMOTE_INPUT只统计真实无线帧。
Linux兼容V1独占固件；实现共存必须更新到V2，原无线15字节协议不变，无需更新发射端。
超长行丢弃到LF，防止残片被解释成新命令。
串口每轮最多处理64字节，处理入口也检查主机超时，避免连续诊断流量饿死运动任务。
2026-10-16已烧录并校验Linux控制扩展，四方向悬空履带测试确认编码器变化和到期归零；
高频诊断下强制结束主机进程，184.8ms观测到主控归零并解除允许。
实机报告见仓库 `project/ctrl/README.md`；本次未自动测试位置机构运动或机械端点。

## 重启后不可控修复（2026-10-21）

实机确认两项原因：Linux的临时串口ACL重插后丢失，Qt报权限不够；七舵机冷上电后模式为
`1 1 1 0 0 0 0`、力矩均关闭、ready_mask=0，而旧固件仅允许显式PREPARE_REMOTE。
无线中立帧正常到达，因此不是遥控配对丢失。

Linux现用匹配CH343型号与序列号的udev规则，赋予cat组读写权限，重启/重插后生效；
控制器失败后每2秒只读重连，不恢复旧动作，手动断开取消重连。
主控新增自主准备及 `STARTUP_STATE phase error`，phase为WAIT_SERVO/WAIT_NEUTRAL/PREPARING/
READY/FAILED/MAINTENANCE；error 1=坐标或力矩读取，2=错误模式下有力矩，3=底盘准备，
4=位置轴准备，5=最终就绪检查。显式维护暂停仍需RESUME_REMOTE，故障不无限卸力重试。

Qt未运行时从实际冷上电状态恢复到模式 `0 0 0 1 1 1 0`、ready_mask=23、遥控允许，
四位置轴反馈保持一致；再次复位单片机后仍READY。日志与升级前64KB备份在主仓库
`build/boot-recovery-2026-10-21/`。完整整机断电重上尚需现场复核，不能将MCU复位等同整机电源循环。
