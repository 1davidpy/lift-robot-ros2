# 重启后的手动抬臂与升降位置控制

## OpenArm 手动抬臂

开机仍然只读采集，点击网页“抬臂到启动姿态”后才使能并运动。

2026-10-22 发现重启后的左 J6 反馈约 0.877 rad，超过软件上限 0.785398 rad；原先的启动前限位检查会直接拒绝。

显式启动允许 J1–J7 当前姿态在原限位外最多 0.15 rad，按目标指令最高 0.15 rad/s 向限位内、启动目标方向恢复。目标限位本身没有扩大。夹爪单独使用更小的 0.02 rad 恢复余量，处理失能时被动位置超过软件边界的情况（现场左夹爪低于下限约 0.013 rad）。零位、正常目标限位保持不变；恢复保持命令仍严格检查原限位。超过余量仍拒绝启动，并在网页显示具体机械臂、关节、位置和限位。

恢复过程的最终发送指令也限制在 0.15 rad/s；停止时保留最后的支撑目标，不会因再次套用关节限位而补跳。原静态补偿、超时和反馈丢失处理保留。

## 升降行程位置控制

1. 在网页“升降行程位置控制”中点击“开启位置控制”。此时只读取固件配置，不移动。
2. 拖动滑条或输入毫米数值，选择 −180 到 +180 mm 的目标，最多三位小数。
3. 点击“移动到目标”，执行一个有限的绝对位置运动。滑条拖动本身不发送运动命令。
4. 到位并确认锁定、READY 后才能发送下一个目标。
5. 点击“停止并退出位置控制”可全局停车。页面关闭、失去焦点、断网或反馈故障会撤销本页控制许可；不会自动恢复或重放目标。

网页会话通过 `/api/lift` 转发至 `/luxi/lift/control`：`position_arm`、`position_heartbeat`、`position_move`、`position_stop`。`detail` 为 JSON 字符串，含唯一 `owner`、递增 `sequence`；移动另含递增 `task_id`、整数 `target_um`。网页每 75 ms 续租，升降驱动使用独立的 1000 ms 上层租约，由 `LIFT_EXTERNAL_LEASE_MS` / ROS 参数 `external_lease_ms` 配置（200–2000 ms）。此配置同时适用于直接 ROS 外部控制入口，不改变电机 UART 的 100 ms 心跳、300 ms ACK 时限或 MCU 的 500 ms 失联保护。Stop 保留原全局停车入口。

与 Quest 统一控制或其他外部会话互斥。驱动仍验证串口独占、反馈、固件版本、参考坐标、READY、运动 ACK、心跳和到位反馈。网页绝对目标可以使用固件确认的完整 ±180000 µm 范围；原 Quest 握键目标仍保留 5000 µm 的内缩余量。

管理模式由 `Project/robot_bringup/config/lift.env` 的 `LIFT_DASHBOARD_POSITION=true` 开启此入口。`LIFT_ALLOW_MOTION=true` 提供硬件运动许可，单纯开机或启动服务不会建立控制会话、不会运动。

网页心跳请求超过 350 ms 无响应时，仅在有效租约内重试心跳；明确拒绝或超时仍撤销许可，不重放运动。升降驱动忽略同一有效 owner 的旧心跳而不续租，避免旧 HTTP 响应/乱序请求误撤销新会话；过期会话不允许恢复。停车原因拆分为 `external_lease_expired`、`recorder_failure_menu` 和原硬件故障原因。状态提供 `external_lease_ms`、`external_heartbeat_age_ms`、`external_max_gap_ms`；systemd 日志记录停车前状态和租约年龄。

UART Python SDK 位于 `device/R680/mcu/stm32-f103-c8-t6_-chip/Projects/lifting_platform_servo/tools/lift_uart_client.py`。`connect()` 后独立线程负责收发、100 ms 心跳和故障检查，调用方的 `on_sample` / `on_ack` 回调不会阻塞该线程。SDK 保持单命令调用方，务必在 finally 中 `close()`；不要与 ROS 驱动同时打开串口。说明见该子仓库 `Projects/lifting_platform_servo/docs/uart_session_worker.md`。本次未修改或烧录 MCU 固件。

## 2026-10-22 实机测试

用户确认现场清空、停止手动操作后，通过网页按钮执行以下测试：

- 抬臂从未使能状态启动，约 11.2 秒反馈到位；连续观察保持超过 72 秒，最大误差从 0.0168 rad 收敛至 0.0111 rad，16 轴反馈持续有效，左右夹爪读数均为 0 rad。最终保留到位后的转矩保持。
- 升降从 −43.506 mm 移至 −38.506 mm，再返回 −43.506 mm。两次均返回 reached、READY、速度为零，无故障；最终退出控制、无会话。未执行全行程实机往返，±180 mm 端点由滑条选择验证和 PTY 固件模拟测试覆盖。
- 记录中电机速度反馈存在瞬时波动，峰值约 1.004 rad/s（右 J5）。0.15 rad/s 是位置目标指令的变化率限制，不是电机实际速度的硬上限；页面已明确此区别。此次未调整底层电机增益或增加实际速度闭环限制。

实机采样记录：`log/arm-web-real.jsonl`、`log/lift-web-real.jsonl`；最终状态：`log/reboot-lift-real-final.json`。

## 心跳修复后的 50 mm 实机往返验证

用户确认现场安全后，网页与 UART Python SDK 分别执行 +41.330 → +91.330 → +41.330 mm。网页两次反馈到位耗时约 7.56 / 7.44 秒，实际端点 +91.329 / +41.330 mm，故障码为零；上层续租最大间隔 416 ms，没有中途撤销或重放目标。

SDK 首轮测试中设备已返回起点，但慢回调下到位确认超时，定位为连续两帧判定把前一帧重新按当前时刻计算年龄。已修正为前一帧在接收时有效、最新帧在判定时仍有效，保留连续序号/设备时间、250 ms 最新电机反馈年龄、位置/速度/故障及锁闸输出检查；新增 100 ms 遥测、200 ms 电机反馈年龄、600 ms 慢回调的回归用例（修复前失败，修复后通过）。

修正后 SDK 完整复测通过，两次到位耗时约 6.85 / 7.46 秒，实际端点 +91.329 / +41.330 mm。27 次回调各暂停 600 ms，158 次 UART 心跳最大间隔约 123 ms；仅发送两条 MOVE，未中途停止或重放。最终关闭会话并恢复升降服务，位置 +41.330 mm、速度零、故障零、未使能、无会话。此次没有修改 MCU 固件。

记录：`log/lease-fix-web-roundtrip.jsonl`、`log/lease-fix-sdk-roundtrip.jsonl`、`log/lease-fix-sdk-roundtrip.json`、`log/lease-fix-roundtrip-final-state.json`。首轮 SDK 超时记录保留于 `log/lease-fix-sdk-roundtrip-initial.*`。
