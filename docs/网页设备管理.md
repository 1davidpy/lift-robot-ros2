# 网页设备管理与重连

网页地址为 `http://板端IP:8000`。网页服务 `luxi-web.service` 开机自启，与 CAN 和相机采集分开；设备不存在时仍可访问网页。

## 操作

1. 在板端读取 `log/web-control.token`，在网页顶部输入并登录。令牌不写入浏览器持久存储。
2. 在 Quest、OpenArm、底盘以及各相机对应位置开启采集。服务运行状态与传感器在线状态分别显示；运行中但没有反馈仍显示未就绪。
3. 在遥操作控制区开启“控制与录制程序”。这只启动程序，不使能电机。
4. 确认反馈正常、Quest 持续发送数据后，使用原有使能按钮。录制默认要求三个配置相机均就绪。
5. 管理服务前先撤销双臂使能、底盘停车并结束录制，然后可关闭采集或重启重连。双臂“暂停 / 返回”包含返回运动；“撤销双臂使能”是独立操作。

掉线后相机驱动自动重试。USB CAN 被移除或替换后释放旧连接，由服务重新加载驱动、按 USB 序列号与物理通道识别接口并启动采集。恢复不会自动使能电机。用户主动关闭服务不会被自动重启。

## 安装与维护

```bash
./tool/build.sh --packages-select luxi_device_adapters luxi_web_ctrl
Project/luxi_web_ctrl/scripts/install_service.sh --web-only
Project/luxi_web_ctrl/scripts/install_management.sh
```

管理安装不会自动开启电机或全部相机。独立单元为 `luxi-openarm-monitor`（兼容旧名称，现为可接收显式使能的双臂采集）、`luxi-base`、`luxi-quest`、`luxi-program`、`luxi-rgb-head_rgb`、`luxi-rgb-left_wrist_rgb`、`luxi-rgb-right_wrist_rgb`。旧的整套 `luxi-robot` 与独立设备服务互斥，使用本模式时应禁用旧整套开机启动。

开关控制本次服务运行状态，不改写开机选项。网页始终自启；设备若需要开机采集，可在板端用 `systemctl enable 对应服务` 设置。CAN 准备脚本在每次采集启动时加载匹配本机内核的 `kcan.ko`，不再依赖手动加载或临时底盘单元。

`GET /api/devices` 提供服务状态。`POST /api/devices/<设备>` 接受 JSON `{"action":"start|stop|restart"}`（实际传单一动作），要求控制令牌。设备与动作均为固定白名单；root 辅助程序只调用指定 systemd 单元，禁止网页传入命令或路径。原有键盘测试控制继续保留无需令牌的行为。

USB 扩展坞若导致系统日志出现 `HC died` 或反复 USB 枚举失败，软件会重试并如实显示离线，但无法替代 USB 控制器、供电或线材恢复。不要把服务运行中视为 USB 物理连接已经恢复。

## 本机验证（2026-09-11）

已验证网页登录、七个管理入口、非法/未授权请求拒绝、服务开关与重启。双臂与底盘采集进程在未使能状态下模拟异常退出，均被自动重启并恢复真实反馈；没有执行电机使能或移动测试。网页服务已检查为 enabled，未为验证而整机重启。

首次连续 60 次采样中双臂和底盘均为 60/60 新鲜反馈；头部 RGB 56/60，右腕 RGB 10/60。右腕发生系统级 USB disconnect，随后重新采集成功，仍需观察扩展坞稳定性。左腕配置序列号 `00DB1265540` 未检测到；Quest 接收程序运行，但没有接收到手柄数据。操作界面截图和采样分别保存在 `log/device-management.png` 与 `log/device-management-test.json`（后续测试会覆盖）。

最终复测：连续 60 次采样，双臂、底盘、控制程序、头部 RGB 与右腕 RGB 均为 60/60 新鲜/就绪；左腕仍未检测到。浏览器服务停止/重启测试、HTTP 权限与参数验证、双臂过期状态显示，以及隔离环境下相机缺失与自动恢复回归均通过。右腕之前发生过 USB 掉线，这次短时通过不代表扩展坞长期稳定性已经确认。
