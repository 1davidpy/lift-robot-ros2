# 升降正常停止后重复使能：CAN 错误分类修正

## 实机证据与原因

2026-09-24 操作者确认左右中指握键分别下行/上行，松开能够停止，但需反复点击使能。原始证据位于本工作站 `/home/robot/luxi-lift-input-diagnostics-20260924/v22-grip-test.jsonl`。

正常松键走 `cancel(..., true)`，保留使能。随后收到 CAN 错误通知，旧适配器不分类型直接抛出异常，撤销使能并清除反馈。这是反复使能的直接原因；不是正常松键主动撤销权限。

本次捕获 18 条错误通知：5 条位填充错误、12 条发送错误（位置字段为 ACK slot），以及 1 条控制器通知。连续发送错误的计数达到 96。KCAN 驱动在警告状态中只对 `counter > 96` 填写细节位，因此计数恰为 96 时可能出现 `CAN_ERR_CRTL` 加全零数据，不能当作“无错误”。没有捕获 bus-off，也没有证据证明物理链路已经稳定。CAN 参考地、终端、接头和干扰原因仍待排查。

## 源码改动

- 单次仲裁丢失、协议帧错误、ACK 错误、BUSERROR 作为诊断记录；它们不直接撤销使能、不清除完整反馈、不改变命令/心跳计时器，也不重发新目标。
- 控制器通知（包括细节全零）、收发器故障、bus-off、重启、发送超时、协议过载、未知错误类型、错误计数达到 96 仍撤销权限。恢复通信不会自动使能或重放运动。
- 原有 Quest、应用 ACK、完整遥测及位置/传感器保护检查不变。错误帧不能刷新反馈新鲜度。
- 原始 CAN 记录保留；新增 `lift_can_error_v1` 事件及状态计数，区分诊断与致停错误。

此改动只处理主机对普通帧错误的过度反应，不能修复布线或电气故障；本次实机捕获的警告级错误仍应停止。
