## 接线检查

协议要求 CAN_H 对 CAN_H、CAN_L 对 CAN_L、GND 对 GND；确认是否已有公共参考地。两端各 120 Ω 终端，断电时 H/L 之间应约 60 Ω。检查底盘和收发器供电、是否接在正确 CAN 口、H/L 是否接反，以及下位机是否运行对应 OMNI 固件并配置为经典 CAN 1 Mbps。

USB-CAN 的 FD 能力不妨碍经典 CAN，但底盘口必须关闭 FD。文档中板载 can0 示例不对应本次 USB CH3。仅接 H/L 不能据此确认共地、终端、供电与固件都正确；本次错误统计不能单独定位其中哪项故障。

## 网页 WASD

网页地址 http://192.168.3.179:8000 。刷新后直接操作，无需密码或令牌（2026-09-14 已移除）。

新增“启用 WASD 测试”，与 Quest 启用入口分开，不需要伪造 Quest 数据。只有反馈有效、FlagStop=0、无录制菜单且未启用其他控制时才可进入；只读诊断模式禁止启用。

W 前进、S 后退、A 左移、D 右移；最大平移速度 0.05 m/s，组合方向按向量限幅，不产生转向。松键发零速；空格、Escape、失焦和切换页面撤销许可。服务端超过 200 ms 未收到键盘心跳撤销许可并周期零速；反馈超过 100 ms 暂停，超过 250 ms 撤销许可。恢复网络后需再次启用。

当前诊断节点无发送。接线恢复并持续收到有效反馈后，先停止诊断节点，再用同一真实驱动启动控制模式：

```bash
source /opt/ros/humble/setup.bash
source build/install/setup.bash
ros2 run luxi_device_adapters r680_adapter --ros-args \
  -p mock:=false -p allow_hardware:=true -p interface:=luxi_base
```

首次实车方向验收按厂商协议架空驱动轮，现场人员准备独立急停。CAN 控制必须为唯一运动来源。当前固件不保证失联后快速停车，主机周期零速也不等于硬件急停。

测试脚本 tool/test_r680_keyboard.py 使用独立 ROS_DOMAIN_ID=86、mock 底盘和 8001 端口，通过真实浏览器键盘事件验证软件。模拟结果不能替代实车执行反馈。
