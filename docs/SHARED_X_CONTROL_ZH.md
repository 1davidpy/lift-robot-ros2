# X 统一使能与双臂归位失能

2026-09-24 更新：短按 X 恢复双臂归位后失能；升降只原位停止，不再自动 HOME。部署与测试记录见 [ARMS_HOME_ONLY_DISABLE_20260924_ZH.md](ARMS_HOME_ONLY_DISABLE_20260924_ZH.md)。

## 按键

| 操作 | 统一模式行为 |
| --- | --- |
| 未使能 / 停止保持时，长按 X 1.5 秒 | 检查全部设备与 Quest；读取升降配置；双臂归位、食指对齐后，开放底盘与升降 |
| 运行中按 X | 请求双臂归位失能；按下时开始，持续按住不重复、不重新使能 |
| 停止保持时短按 X | 松开 X 后请求双臂归位失能 |
| B / 网页“停止全部 / 双臂保持” | 底盘停车、关闭主机升降会话、双臂保持；不归位、不移除双臂转矩 |
| Y | 预留，不再独立切换底盘 |
| 左中指 / 右中指 | 按住下降 / 上升；松手或双键停止；到内缩边界停止并保留许可。换向前须释放两键，新运动等待停稳 |
| 左摇杆 / 右摇杆横向 | 底盘平移 / 转向，仅在统一使能完成后响应 |
| A | 开始录制 / 成功结束；录制中 B 同时打开失败菜单，仍只停止保持 |

使能时及完成对齐时，摇杆须回中、两中指松开。长按被拒绝后须释放 X 再试；按住等待故障恢复不会自动启动。上电或输入中断恢复后也须先释放 X。食指与夹爪映射不变。统一模式关闭独立设备使能入口。

## 正常失能顺序

1. 撤销底盘与升降输入，关闭主机升降会话，双臂保持转矩。
2. 确认底盘、升降、双臂停稳，升降旧会话已关闭。
3. 双臂低速返回 `arms-teleop.json` 的 home，保留当前夹爪目标。升降保持停止高度，不发送 HOME/MOVE，不修改标定。
4. 非夹爪关节误差 ≤0.03 rad、速度 ≤0.05 rad/s，连续 0.5 秒稳定；再次确认设备状态后发送双臂 disable，等待 `enabled=false`。

归位期间设备反馈丢失、Quest 无效、底盘/升降移动或故障均中止归位并保持双臂转矩，不继续失能。通信或电源失效时不能保证实际保持力。用户要求恢复此行为，由操作人员确认当前升降高度下的双臂 home 路径和失能支撑，软件不声称任意高度均有安全支撑。

B 始终走立即停止保持路径，不执行以上归位序列。升降板已保存的上电自动回中策略不因本次修改改变。

## 接口与记录

- `/luxi/control`：`start` 统一启动；`stop` / `park` 双臂归位失能；`disable` / `halt` 停止保持。
- `/luxi/control_status` 包含 `parking_policy=arms_home_lift_stopped`。
- `/luxi/coordinated_control` 包含操作 epoch、阶段和主机单调时间；设备失去协调消息即撤销本次控制，不自动重启旧动作。
- 协调器使用原始硬件反馈时间计算年龄；升降每个新完整快照立即更新状态，未放宽反馈、心跳或 CAN 故障门槛。
- `/luxi/lift/state` 保存实测 `speed_rpm`、高度、状态和时间戳。`speed_rpm` 是电机有符号转速，不是直线关节 m/s。原始 episode 的 `bag/` 保存该话题及请求/ACK、原始 CAN、协调状态。
- 现有 LeRobot v2.1 的 19 维双臂+底盘布局未在本次新增升降维度，不能把原始 bag 已记录升降等同于转换结果已含升降。

`LIFT_ALLOW_MOTION=false` 时统一使能会被拒绝；这是禁止运动加载模式。重新测试前应确认实时反馈和现场条件，再明确恢复运动许可。真实 CAN 错误导致的停机保护仍保留；取消停用时的升降回零不等于 CAN 链路问题已经解决。
