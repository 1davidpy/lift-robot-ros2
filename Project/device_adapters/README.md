# luxi_device_adapters — 硬件 SDK 边界

openarm_adapter 负责 SocketCAN 电机协议和实际反馈；hikrobot_camera 负责 MV3D RGB-D SDK。kh_can_setup 负责鲲弘四路识别和配置，见 ../../device/KH-UCANFD-B2B-X4/README.md。mock 为默认；test_camera 使用假 SDK，test_kh_can 检查身份和映射，socketcan_probe 提供只读/虚拟总线验证。

构建：在仓库根目录运行 `bash tool/build.sh`。验证：`bash tool/test.sh`。产物统一在 `build/`，日志在 `log/`。

完整接口和限制见 [迁移与接口说明](../../docs/CPP迁移与接口说明.md)，运行步骤见 [仓库 README](../../README.md)。

新增 `r680_adapter`：三轮全向底盘经典 CAN 驱动，接收 Quest 左右摇杆、执行底盘独立许可和看门狗。协议、PS2 倒车转向约定及部署见 [R680 说明](../../device/R680/README.md)。默认 mock，不修改 STM32 固件。

Quest 左摇杆控制前后/左右平移，右摇杆横轴控制转向。短按 Y 切换底盘许可：未启用时请求启用，已启用时停车并撤销许可；网页仍可独立启用/停车。长按不重复切换，Y 不再取消录制。`require_left_grip` 默认 `true`，保留原来的左握持键行驶许可；托管启动脚本设为 `false`，启用后直接使用摇杆，给未来升降控制预留两侧中指握持键。启用仍要求摇杆回中、有效跟踪和新鲜底盘/Quest 数据；启用被拒绝后必须松开 Y 再按，不能按住等待自动启用。启动或断线恢复时同样需要先收到松开 Y 的有效输入。回中立即下发零速，不经过加速斜坡；B、INVALID 跟踪、数据超时、底盘故障和录制失败菜单都会停车并撤销许可，恢复连接不会自动重新使能。同时按 B 和 Y 时停车优先。X 只控制双臂，不改变底盘许可或摇杆运动。只读诊断模式禁止 Y 启用。普通 STALE (1) 接受新鲜摇杆输入。底盘状态发布实际 `require_left_grip`，网页据此显示操作提示。

`base_quest` 隔离测试启动 mock 底盘，包含 STALE/INVALID、直接摇杆与握持键互不影响、回中停车、断线不自动恢复、B/Y 停车和录制菜单用例。新增 Y 切换用例包含长按单次、非回中拒绝后重新按键、断线/启动时按住 Y、B 优先、键盘许可切换和只读模式，并新增 X 短按/长按/松开均不改变底盘许可或摇杆运动的用例；已构建；8 个底盘用例连续三次全部通过，详见 [测试记录](../../docs/Quest_button_mapping_validation_20260915.md)。测试发送端采用深度 1 的最新输入队列，并在服务断言前等待输入确认，避免旧输入造成的假失败。未重启实机服务，新映射下次启动生效。实机方向与停车仍需现场操作确认。升降硬件未安装，本次不发送升降指令。
